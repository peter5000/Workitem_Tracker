1. The Intake Funnel (Inbox & Someday)
Triage Inbox: A single raw text file or quick-capture column for bugs, ideas, or architectural thoughts. Do not categorize or estimate during capture.

Someday / Cold Storage: Stale ideas go here. Never let uncommitted ideas sit in your active backlog—large backlogs induce guilt and decision fatigue.

2. Project Scoping ("Pitching")
Before creating work items for a feature, write a 3–5 bullet spec defining:

Appetite: How much time is this worth? (e.g., "One weekend", "4 evenings").

Boundaries: What is explicitly out of scope for v1?

Definition of Done: What observable behavior proves this is complete?

3. The Execution Board (Strict WIP Limits)
Set up a board with these exact columns and constraints:

[ Backlog ] ──> [ Ready (Next 3-5) ] ──> [ Doing (Max 2) ] ──> [ Done ]
                       │
                       └──> [ Blocked / Waiting ]
Ready: The exact items you plan to work on next, pre-sliced into 1–3 hour tasks.

Doing (WIP = 1 or 2): Never exceed two items in flight. If you hit a roadblock, move it to Blocked or push it back to Ready; do not just open a third task.

Granularity Rule: If a task takes longer than 4 hours, it's not a work item—it's an epic. Break it down into testable units.

4. The Cadence (Weekly 15-Minute Reset)
Pick one day a week (e.g., Sunday evening) to run a 3-step loop:

Clear the Inbox: File items into the active project, move them to cold storage, or delete them.

Review WIP: If a card has been in Doing for more than 5 days, either kill the scope, slice it smaller, or admit you aren't working on it.

Queue the Next 3–5: Commit to the specific items to complete in the coming week.
